# Accepted frontend execution

The required workflow derives its affected-input plan from the clean current
checkout. When that plan permits frontend omission, the workflow requests an
independent accepted-proof admission. Refusal selects the complete frontend
families before jobs start. Source-only planning remains a distinct observation;
it does not establish previously executed browser coverage.

Admission starts with the event's official main baseline. Read-only GitHub APIs
must prove current main ancestry, its merged owning-repository pull request, the
accepted PR head's ancestry and the newest exact-head source-owned Actions run.
The original preview checkout must retain the accepted main tree and the exact
PR head and base parents. The ordinary same-head observation boundary remains
strict unless this process-local accepted-checkout capability is present.

Every original source-owned job must have actually succeeded. Actions physical
check ownership, individual attempts, three engines, whole-job budgets, artifact
upload intervals, expiry and per-ID API digests remain required. Admission reads
the exact producer and complete aggregate plus the original fault and catalogue
artifacts whose native bodies are absent from the complete archive. Acceptance
is limited to fourteen days and to a direct complete producer; an omitted run
does not recursively authorize another omission.

All owned frontend inputs, including unknown inputs, must retain their exact Git
blob IDs and executable modes. Fresh current bytes must match those blobs and
the original physical inventory. Original native Node paths are interpreted
through this admitted Git closure. Receipt bodies, source heads, paths, run IDs
and actual attempts remain unchanged.

Verification reconstructs the original fixture and installed package bytes,
reopens the current canonical project contracts, checks every original group and
JUnit result, and requalifies renderer, publication, persisted-reader, catalogue
and intentional fault evidence. Runtime reuse also requires the exact Node/npm,
platform and runner image identity; mismatch conservatively selects fresh work.

Navigation and the required report independently reopen admission. If a selected
proof expires, changes or fails native requalification, these required contexts
fail. They cannot quietly turn skipped jobs into fresh successful executions.
The report records zero current frontend cases and nests the unchanged original
source, producer, counts and API artifact pointers. Current standard and contract
contexts remain required. Physical devices and human assistive review remain
outside the headless proof.

The manual workflow defaults to full current execution. Its explicit
`accepted-proof-qualification` choice is eligible only at the exact current
accepted `main` checkout. Live APIs must independently bind that checkout and
this owning workflow-dispatch run and attempt. This event remains a dispatch;
it does not become a pull-request producer. Only a healthy normally accepted
pull-request producer can supply the original complete proof.

The producer's API actor and triggering actor must both match the merged pull
request author's exact login and positive numeric user ID. The qualification
run's API principals must independently match its actual `GITHUB_ACTOR` and
`GITHUB_ACTOR_ID` environment. Missing principals and another user's rerun
conservatively refuse reuse, even when that user could legitimately execute a
full workflow. Receipt fields and Git author text cannot establish this boundary.

Eligible selection and each required aggregate revalidation execute the current
source-owned CLI inside the package producer's pinned Playwright image. The
current Node executable and installed npm package are mounted read-only, and
all live API capabilities are created inside that process. The image observes
its own platform rather than inheriting the host's image labels. Missing tools,
failed launch or invalid proof selects full execution before jobs; loss of proof
after selection fails the required aggregates. Ordinary full execution remains
on its existing runners.
