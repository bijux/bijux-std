# Browser job ownership

The canonical partition registry still owns every suite, viewport group and
engine assignment. The batch registry assigns each complete canonical group
to exactly one physical job for each engine. Related groups share one setup,
fixture download and npm package admission. Their original group directories,
case identities, engine receipts and JUnit files remain separate.

An API-created batch artifact capability owns only its declared group roots.
Every group keeps an execution declaration whose original group identity is
checked against the physical batch job, producer envelope and exact artifact
bytes. Missing groups, foreign roots, swapped declarations or skipped jobs
refuse aggregate qualification. The complete physical job, including setup,
transfer, uploads and cleanup, must finish in less than 180 seconds.

The consolidation was bounded by retained complete-job and step observations
for the accepted source. Those timings guide selection; they do not prove a
cost saving or admit changed source inputs. A fresh complete candidate remains
necessary for its current source bytes and collected case inventory.
