# Current-source verification selection

The standard and contract checks run for every admitted human pull request and
merge-group checkout. The frontend family includes fixture generation, all 27
browser groups across all three engines, renderer controls, publication command
controls, catalogue controls, browser and public fault controls, and the persisted
reader. Its dependency closure is indivisible until a narrower owner contract is
reviewed.

The planner reads immutable Git tree objects and original changed-input records.
It checks the event baseline against the official repository's fetched main
reference and checks that the planner and canonical workflow are unchanged from
that baseline. Known repository governance or metadata changes can leave the
frontend family unselected. Unknown ownership, deletions, renames, altered planning
sources, invalid source materialization, or unavailable baseline identity select
the complete family.

The current-head navigation aggregate and required report always execute. They
recompute the plan, compare the actual job selection, and require success for
selected jobs and explicit skipped outcomes for unselected jobs. Unselected
families are never reported as executed at the current head. Accepted original
execution is a separate proof qualification with unchanged original identities.
A later workflow attempt recomputes selection and retains an execution-pending
observation until the existing same-head, API-created execution admission verifies
actual physical jobs and receipts. Source-only selection still checks actual
source and aggregate contexts.

Native operation clocks retain source inventory, runtime inventory, npm
installation, and receipt-writing observations in existing runner logs and ignored
artifact journals. These cost observations do not provide source identity,
publication approval, or execution authority. Python `seconds` exclude nested
operation intervals, so summing those values does not count the same runtime
inventory twice. `wall_seconds` and `nested_seconds` retain the original clock
boundaries. GitHub step timestamps remain the
owner of setup, transfer, reporting, and teardown timing.
